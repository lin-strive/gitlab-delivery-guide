# 虚拟机网页测试

适用于在指定虚拟机中打开真实应用页面、执行浏览器自动化和保存验收证据。部署方式按项目已确定方案实施；本文只说明如何核验和控制目标 VM 中的浏览器。

## 浏览器运行位置与控制方式

分别记录 Agent 所在宿主机、构建节点、应用部署目标及测试 VM 的身份和访问方向。应用部署位置与浏览器执行位置分别核验，不能由页面 URL 推断浏览器运行在哪台机器。

按实际可用工具选择控制方式：

- 在 VM 内运行项目已有浏览器框架或适用的浏览器 CLI，通过已核验的 SSH/远程维护通道调用。可见模式使用 VM 当前用户的真实图形会话和用户指定的兼容浏览器。
- 需要接管已启动的测试浏览器时，使用框架支持的浏览器调试连接。调试端口只绑定回环地址，跨节点使用受保护的通道；不暴露到公网，不复制用户日常浏览器的登录配置来接管会话。
- 使用原生桌面适配器操作虚拟机窗口时，先验证截图、焦点和控件访问能力。网页 DOM 与原生窗口控制是不同能力；能力不足时准确交接人工步骤，不臆造接口。

同一工具或会话足以完成任务时继续复用，并遵循所选工具的当前规范。此 Skill 不捆绑远程控制工具。

## 首次预检与执行证据

先用无副作用操作验证实际 hostname/VM 身份、浏览器可执行文件及会话、页面 URL、部署版本、一个真实控件定位和脱敏截图。尚无应用时，先用无业务数据的页面验证框架，明确应用尚未检查。

宿主机打开相同网址、SSH 可用、浏览器版本号、HTTP 200 或单独的 headed=true 都不能替代指定 VM 内的页面验证。`localhost` 指向浏览器所在机器，测试地址应以目标 VM 的实际访问结果为准。

测试时检查页面内容、必要业务断言和浏览器实际报错，不能只验证窗口打开。遇到网络、证书、权限或会话问题时，保留真实证据并按项目环境排查，不关闭保护、忽略证书、伪造返回或改变部署目标来冒充测试通过。

## CI 与交互式排错

日常测试由指定 VM 的 Runner 执行；Agent 可以通过远程维护通道在同一 VM 中交互式定位问题。分别保存 CI 作业与交互式排错的结果，不能把一次手工操作写成持续流水线已实现。

可见浏览器与其他桌面任务协调会话占用，避免并发作业或宿主机窗口抢走焦点。测试前后核对当前应用版本，报告中同时记录应用提交和测试脚本提交。

## 中断与接续

工具报告用户停止控制时，立即停止后续界面输入，保留最后已知页面、任务/请求标识、已提交操作、结果和待办。记录中不保存秘密。

恢复时先核实页面与服务端状态。超时、断线、窗口消失或停止控制不证明写入未执行；结果未知时不自动重复提交。复用项目已有防重复和恢复规则，不能为通过验收重置业务数据或删改断言。

按本次实际范围报告通过、失败及未完成部分。用户转向独立任务不代表授权恢复被停止的操作。
