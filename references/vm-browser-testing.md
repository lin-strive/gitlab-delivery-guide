# 虚拟机网页与设备测试

适用于指定 VM 的可见网页测试、浏览器连接本机 SDK、应用与测试同机部署，以及有物理副作用的接续测试。地址、工具、运行时和设备型号均从当前项目调查，不预设宿主机或虚拟机能力。

## 1. 证明浏览器运行在目标 VM

先区分四个位置：Agent 所在宿主机、构建 Runner、应用部署节点、浏览器/设备所在节点。可以分开，也可以经用户选择共用 VM；记录各自身份和访问方向。

按可用能力选择控制方式：

- 在 VM 内运行项目已有浏览器框架或适用的浏览器 CLI，通过已核验的 SSH/远程维护通道调用；可见模式使用 VM 当前用户的真实图形会话和用户指定的兼容浏览器。
- 需要接管已启动浏览器时，可使用框架支持的浏览器调试连接。调试端口只绑定回环地址，跨节点使用受保护的通道；不把端口暴露到公网，不复制用户日常浏览器的登录配置来接管会话。
- 原生桌面适配器可以操作 VM 窗口，但网页 DOM 控制和 VM 内 SDK 原生对话框是两种能力，分别核验。工具不能访问原生窗口时，准确交接该窗口的人工动作。

先用无副作用操作验证：实际 hostname/VM 身份、浏览器可执行文件与会话、页面 URL、部署版本、一个真实控件定位及脱敏截图。保存非敏感控制方式和证据位置。宿主机打开相同网址、SSH 可用、浏览器版本号或 HTTP 200 均不能替代这项检查。

同一工具或会话已足以完成任务时继续复用。使用工具当前提供的能力与操作规范，不能臆造浏览器、原生桌面或跨 VM 控制接口。此 Skill 不捆绑远程控制能力。

## 2. 页面与本机 SDK 的链路

`127.0.0.1`/`localhost` 指向运行浏览器的机器。先调查 SDK 实际协议、监听地址、端口、进程、版本及驱动，逐层验证连接、初始化和状态查询；不能沿用另一系统的默认端口。

诊断页与业务页需使用同一份工作站连接设置，保存后通过业务页真实重连验证。按浏览器保存的设置属于当前工作站；更换 origin、浏览器配置或用户后需重新确认，不能把它当成全局部署参数。

发生本地网络访问或混合内容错误时，读取浏览器实际控制台和网络结果，再对照当前版本官方要求。命令行能连 SDK 不证明网页能连；也不能把浏览器拒绝连接误判为 USB、服务或业务接口故障。

调查两种适用方案，按用户选择落实：

1. 应用保持远程部署，使用浏览器信任的 HTTPS 入口，并通过正常的站点权限流程访问本机服务。先核验现有证书、可用入口和网络条件，再决定是否准备新的入口。
2. 把所需应用前后端真实部署在设备所在 VM，从 VM 回环地址访问本机应用。核对实际页面的安全上下文及 SDK 连接；现有数据库、对象存储和外部业务服务可以继续远程复用。

按用户已确认的目标实施；改变部署位置时补齐目标和范围。明确应用实际运行位置，不能把转发后的页面误报为应用已部署在 VM，也不能掩盖浏览器权限问题。不要用关闭浏览器网络保护、降级浏览器、忽略证书或伪造成功返回解决失败。

依据：[Chrome 本地网络访问](https://developer.chrome.com/docs/modern-web-guidance/guides/security/local-network-access)、[W3C Secure Contexts](https://www.w3.org/TR/secure-contexts/#is-origin-trustworthy)。浏览器策略以实际版本和运行结果为准，不在 Skill 固定版本号或要求所有项目都迁到 VM。

## 3. 应用部署到测试 VM

构建可继续在原 Runner 完成，VM Runner 只接收绑定版本且校验通过的产物并部署。调查 VM 是否有合适的容器环境；也可按系统能力使用用户服务、原生进程管理器等，不为了部署强制安装 Docker。

- 前后端都纳入发布包与版本核验。静态页面部署需验证 SPA 路由、静态资源、同源 API 代理、上传和业务写请求，检查 Host、Origin 与后端跨域配置；只加载首页不代表前后端接通。
- 运行时以 VM 实际能力为准。脚本语法、标准库接口、ABI、CPU 架构和运行库都需适配；构建机器通过不证明 VM 能启动。
- 保持发布目录不可变。日志、扫描图像、业务数据及解释器缓存放到独立位置，或使用运行时支持的禁写缓存选项；服务启动后再次核对产物，避免运行产生的文件破坏后续校验和回滚。
- 启动入口、受保护配置与发布版本分开管理。执行保护确实拦截时，先完成代码与相关校验，再列出已核验的具体文件供管理员处理。稳定入口按版本/摘要校验后复用；修改入口后重新核验，不递归信任目录，不换解释器绕过拦截。
- 调查既有数据库、对象存储和外部服务，记录复用/新建及检查方式。复用时仅发布应用，保留原连接与数据，不因模板自带依赖就创建替代服务。凭据通过已授权的受保护通道交付，不进入仓库、发布包或报告。
- 备份可以留在有权限的原节点，VM 只接收版本、备份位置和配置一致性等必要元数据。应用回滚与数据库恢复分别评估。
- 切换部署目标时，协调原有与新的发布流程，防止旧作业继续覆盖旧目标。按已确认迁移范围，在新服务及必要验收通过后停用旧应用，保留约定的恢复资料及复用数据服务。

检查用户服务在退出登录、重启和重新登录后的行为；可见浏览器仍需要实际图形会话。虚拟机需按约定保持开机和联网。不要把首次框架预检、部署健康和后续功能验收混为一个通过状态。

## 4. 软件测试与真实设备分开执行

常规 CI 先落实明确范围的软件测试；需要防止真实设备被误操作时，在该测试上下文实际阻断设备连接及业务写操作。不要把这个隔离上下文直接拿来证明实机可用。测试替身只证明所声明的软件断言，不能作为真实硬件成功证据。

用户授权真机测试后，复用已确认范围，记录设备、允许动作/次数及人工步骤。VM 中要实际识别到控制器和相机等必要外设；宿主机可见不代表已交给 VM。USB 兼容性、带宽与独立采集可用于定位故障，具体控制器版本按实测选择，不固定推荐某一种。

按业务实际阶段执行并保存证据：页面操作、服务端请求标识、SDK 返回、真实图像/实物结果、计数及外部回传。传输接收确认、进度帧或 SDK 返回成功，不自动等于物理动作成功，也不自动代表业务归档完成。只发送本次范围内必要动作。

装纸、取纸、换物料等真实人工步骤必须实际完成，不能通过勾选框或伪造状态代替。不得把未经厂商定义的字段当作传感器证据。保留真实设备与业务审计记录；清理测试进程/会话不等于删除真实业务结果。

## 5. 中断与恢复

工具报告用户停止控制时，立即停止后续界面输入并交接最后已知状态。需要续接的信息包括：任务/请求标识、已发出的动作、最后已知阶段、结果为已确认或未知、待人工动作和证据位置；不把秘密写入记录。

恢复后先只读核实应用记录、设备及外部系统状态，再决定下一步。超时、断线、停止控制或窗口消失不证明动作未执行；结果未知时不自动重发物理命令或外部回传。原生定位窗口、已返回结果和未发送请求分别处理。

保持已有的防重复、修订号及业务次数约束。真正的新尝试须符合项目恢复规则和既有授权范围；不能为了让测试通过重置业务状态、改成假返回或自动消耗更多次数。

部署与只读 CI 已通过、真机流程被中断时，分别报告各自结果及未完成范围。用户转向独立任务不代表授权恢复被停止的设备操作。
