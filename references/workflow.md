# 分步引导流程

从最早未通过的必要阶段继续；已有能力直接复用，可以交错准备，依赖未满足时不执行依赖动作。用户只要求规划时才停留在方案。

项目配置保存事实及来源；接入记录保存当前阶段、状态、用户待办、证据和下一步。关键变化后更新，避免中断后从头询问。阶段状态为 pending、in_progress、waiting_user、passed、failed、not_applicable；不适用需说明原因，不能借此跳过必要阶段。

## 1. 识别项目

**自动处理**：解析项目主页/克隆地址、子群组、端口和子路径；检查当前目录、远端、仓库规范与未提交修改。读取项目 ID、默认分支、CI 入口、GitLab 版本和可见 Runner。调查完整仓库的构建描述、锁文件、部署文件、服务、迁移、测试与健康检查，单仓多应用分别识别，保留已有工具链。

**按需提问**：没有地址先问地址；只有 SSH 地址且不能确定 Web 入口时再问网页地址。先检查已有连接、CLI、Git 身份，不立即要求新建 Token 或密钥。

**通过条件**：能读取目标仓库并识别应用和现有流程。无权读取的事实记 unknown，不当作不存在；默认分支仅用于调查，不自动成为部署授权。

## 2. 确定交付方案

**自动处理**：依据仓库和团队配置推荐部署方式及理由，支持容器、服务进程、编排平台或既有发布系统，不强制统一技术。先调查已有服务，确定隔离目录、端口与持久化资源。

**按需依次提问**：

1. 允许自动部署的分支、环境和目标主机/集群。
2. 连接方式、目录/命名空间、端口、数据和服务检查。
3. 指定 VM 及测试形式：可见浏览器、无头浏览器、API 或原生桌面；首轮验证哪些实际行为。

用户不知道命令时由 Agent 根据项目生成，不把实现变成问卷。列出凭据变量名、用途、environment scope、protected/file 类型，指导用户在机器、CI 变量或密钥服务配置；不请求聊天中的密码。

**通过条件**：分支、目标、范围、节点和必要连接有落实方式。未答复可继续准备文件，但不启用未知目标的部署。生产发布和破坏性迁移不从接入测试流程推导授权。

## 3. 接入执行节点

**自动处理**：检查 Runner 的作用域、标签、执行器、OS、在线/暂停/protected 状态与项目可见性。优先复用可信边界内的 Runner，区分构建/部署与 VM 测试节点；锁定项目 Runner 不自动覆盖新项目，群组 Runner 按实际作用域复用。

缺少节点时准备适配系统的安装、注册、自启动和最小检查作业；凭据留在安全位置。检查资源和并发，保护共享主机上的现有服务。Shell 执行器不隔离不可信项目。

**需要用户操作时**：只请求实际缺少的安装、注册权限或本机身份验证，说明机器、账号、文件与预期结果。

**通过条件**：真实 GitLab 作业派到正确节点，并证明身份和工具可用；列表显示 online 不够。

## 4. 通过环境预检

按 [环境检查](environment-checks.md) 先跑不部署的预检，避免构建后才发现桌面不可用。

**通过条件**：源码、依赖、产物、部署访问和测试访问分别可用；VM 身份、架构、持久化系统与资源满足要求。可见模式实际执行定位与脱敏截图，原生桌面验证对应适配器。有已部署应用时检查真实入口；尚未部署用无业务数据的页面检查框架，明确应用未检查。

命令存在、TCP 连接成功、能打印浏览器版本都不能替代预检。缺少会话、驱动、SDK 或远程能力时准确记录。

## 5. 生成与校验项目文件

按 [流水线与报告约定](pipeline-contract.md) 增量实现映射、CI/include、构建、发布、备份、健康检查、失败恢复、测试、清理和运行说明。已有可靠脚本可适配，不要求统一目录和框架。

模板填入真实调查结果，未知内容保持未配置，不生成固定通过或占位部署命令。检查语法、相关测试、diff 和敏感信息。在目标 GitLab 校验父子配置、依赖、变量和触发规则；按实际版本及许可检查等待策略、产物传递和锁，不能只校验最外层 YAML。

**通过条件**：文件具体可审阅，引用和依赖完整，配置检查与真实预检通过，部署目标和凭据范围明确。

## 6. 执行完整流水线

在已授权仓库和分支提交/推送；用户只要求本地准备时交付 diff，并明确尚未实测。

执行：构建/测试 → 产物清单与校验 → 全周期环境锁 → 备份 → 部署 → 全部健康检查 → 指定 VM 测试 → 报告/清理。各步读取真实上游结果，不用重新拉取移动分支构建替代已绑定产物。

失败先区分权限、配置、网络、资源、框架兼容和业务断言，保留证据。不删断言、不关闭校验、不伪造结果。清理失败先精确处理遗留记录，再决定是否重跑。

**通过条件**：实际 CI 完成部署、健康检查、VM 验收与报告回传，版本、节点和范围可追溯。

## 7. 核验与交接

读取父子流水线、必要作业、部署记录、JUnit、结构化结果及脱敏截图。应用与测试脚本提交分别追溯；仅验收旧部署时允许不同，但需各有来源。检查必要断言、跳过项与清理，不仅看构建图标。

标准摘要可用 `scripts/check_result.py` 查一致性；已有格式先适配并保留原始证据。更新接入记录中的配置提交、应用版本、CI 链接、环境、VM、范围、结果、限制与下一步，证据支持后才标 verified。

交接说明后续触发方法、报告入口、失败恢复和需要人工处理的条件。后续调用先读记录并复核运行状态。
